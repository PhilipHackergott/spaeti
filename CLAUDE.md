# Späti — operator instructions (this repo)

You are one operator in a fleet building **Späti**, a 2D HD-pixel-art narrative management sim
("a Berlin Späti version of *Coffee Talk*"). Read `docs/00-pipeline.md` first, then the doc for your lane.
The four docs in `docs/` are short and binding.

## The facts that never change
- **The game is `godot/`** (Godot 4.7.2, GDScript, base grid 480×270 ×4). `app/` is a superseded web prototype —
  read it for the rules port, never build on it.
- **Gameplay = the original plans:** `03-mvp-spec.md` (what), `04-build-plan.md` (how — engine section still
  valid, substrate sections superseded), `game-design-document.md`, `narrative-design.md` (Truby arcs).
- **Look = `art-direction.md` + `docs/art-style-brief.md`**; the bar is `concept-art/main character target state.png`.
- **Art is generated by Codex, never drawn by you.** `node tools/codex/art.mjs --id <id>`; specs in `docs/asset-spec.json`.
- **Codex judges every capture.** `node tools/godot/shot.mjs` → `node tools/codex/judge.mjs`. You fix what the verdict names.
- **Central pool:** every widget is a component in `godot/components/` (`docs/04-component-catalog.md`). No second looks.
- **Engine purity:** `godot/engine/` is pure, seeded, testable headless; scenes consume it.

## Working rules
- Run `node tools/godot/test.mjs` before you say something works. Capture the screen you changed and look at the PNG
  yourself (Read it) before you hand it to the judge.
- Append what you did, what scored what, and what you could not fix to `docs/03-build-log.md`. Keep `docs/04-component-catalog.md` current.
- Tabs in GDScript; static types; `class_name` on reusable scripts; `.tscn` node trees the user can inspect.
- Commit on the current branch (`godot-vertical-slice`) at each coherent step with a one-line "what + why". Never push.
- Never call `codex` or Godot raw for pipeline work — the wrappers in `tools/` encode the Windows traps.
- Never run Godot headless to render; never leave a Godot window or a `codex exec` hanging (the wrappers have watchdogs — use them).
- Do not touch `project-state.json`/the factory registry — the orchestrator does that at the gate.

## Factory context
This folder is a standalone git repo (it is git-ignored by the surrounding BoardGameMVPs factory). The factory's
playbooks are vendored under `factory-reference/` for reading; the stack sections there describe the old web
substrate and do not apply. The human gate still applies: the slice is presented for approval, not auto-shipped.
